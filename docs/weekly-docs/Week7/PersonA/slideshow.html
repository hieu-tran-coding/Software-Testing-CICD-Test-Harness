Khái niệm CI/CD

Bản chất của các giai đoạn tự động hóa trong vòng đời phần mềm
Nhóm 06
Continuous Integration
  • •
    Developer push code lên nhánh chung liên tục (ít nhất hàng ngày).
  • •
    Tự động Biên dịch (Build), Lint và Kiểm thử (Test) ngay lập tức.
  • •
    Mục tiêu cốt lõi: Phát hiện sớm xung đột code, lỗi cú pháp và regression test.
Continuous Delivery
  • •
    Mã nguồn và artifact đóng gói luôn ở trạng thái 100% sẵn sàng để release.
  • •
    Tự động kiểm chứng toàn diện trên môi trường Staging/Testing độc lập.
  • •
    Đặc điểm: Việc đưa lên Production có thể cần phê duyệt thủ công (Manual Gate).
Continuous Deployment
  • •
    Tự động hóa hoàn toàn mọi bước từ commit đến Production thật.
  • •
    Code vượt qua bộ test là tự động release mà không cần phê duyệt thủ công.
  • •
    Yêu cầu: Bộ test tự động phải có độ tin cậy cực cao và có hệ thống rollback tức thì.

Test Harness: Định nghĩa & 4 Trách nhiệm Cốt lõi

Tiêu chuẩn ISO/IEC/IEEE 24765 và sự khác biệt với việc chạy script thông thường
Nhóm 06
Định nghĩa: Test Harness là tập hợp phần mềm, công cụ, stub/driver và môi trường giả lập được xây dựng để thiết lập, điều khiển, quan sát và dọn dẹp quá trình thực thi kiểm thử một cách hoàn toàn tự động và có thể tái hiện.
🛠️

1. Thiết lập (Setup)

Khởi tạo runtime Node 14, cài dependency, migrate SQLite DB, cấp phát Docker network cô lập.

🎮

2. Điều khiển (Control)

Khởi động server nền, chờ smoke probe /api/tags phản hồi, kích hoạt test runner theo thứ tự định sẵn.

👁️

3. Quan sát (Observe)

Thu nhận exit code, xuất báo cáo JUnit XML, quay video Cypress, chụp màn hình lỗi và ghi log server.

🧹

4. Dọn dẹp (Teardown)

Xóa container, gỡ bỏ mạng ảo tạm thời dựa trên build label, đảm bảo môi trường sạch cả khi test thất bại.

pipeline { agent any parameters { choice(name: 'RUN_MODE', choices: ['source', 'image']) string(name: 'IMAGE_TAG', defaultValue: '') string(name: 'SMOKE_PATH', defaultValue: '/api/tags') } stages { stage('Smoke test') { when { expression { params.RUN_MODE == 'image' } } steps { sh 'python3 jenkins/image_smoke.py smoke' } } stage('Cypress UI tests') { when { expression { params.RUN_MODE == 'image' } } steps { sh ''' cypress run --project . \ --config "baseUrl=$CYPRESS_BASE_URL" \ --reporter junit \ --reporter-options "mochaFile=test-reports/junit/cypress-[hash].xml" \ --env "allure=true,allureResultsPath=test-reports/allure-results" ''' } } }
# Post-actions thu thập bằng chứng ngay cả khi thất bại post { always { script { try { // 1. Dọn dẹp an toàn container và ephemeral network sh 'python3 jenkins/image_smoke.py finalize' } finally { try { // 2. Tổng hợp báo cáo JUnit XML cho Test Trend junit testResults: 'test-reports/junit/*.xml', allowEmptyResults: true } finally { try { // 3. Render Dashboard Allure HTML allure commandline: 'allure', results: [[path: 'test-reports/allure-results']] } finally { // 4. Lưu toàn bộ Artifacts (video, logs, json) archiveArtifacts artifacts: 'test-reports/**/*' } } } } } } }

Security Principles

Phía GitHub Actions

  • ✓
    Sử dụng GITHUB_TOKEN tự động cấp phát với quyền tối thiểu packages: write chỉ tại job push image.
  • ✓
    Các bí mật liên lạc Jenkins (JENKINS_URL, JENKINS_TOKEN) lưu trữ trong GitHub Secrets.

Phía Jenkins Server

  • ✓
    Lưu GitHub PAT đọc private registry trong Jenkins Credential Store với ID thống nhất ghcr-credentials.
  • ✓
    Đưa token vào docker login qua standard input (--password-stdin) và ghi vào DOCKER_CONFIG tạm thời; tự động xóa sạch thư mục auth sau khi pull.
Cam kết kiểm toán: Không có bất kỳ token, password hay secret nào xuất hiện trong git commit, console output hay ảnh chụp màn hình minh chứng.
